\section{Tổng quan Phân hệ Cập nhật Tài liệu Tự động (Automatic Documentation Update)}

\subsection{Giới thiệu và Mục tiêu}
Trong các dự án phát triển phần mềm hiện đại, hiện tượng "lệch pha tài liệu" (documentation drift) diễn ra rất phổ biến khi mã nguồn liên tục thay đổi thông qua các Commit hoặc Pull Request (PR) nhưng tài liệu không được cập nhật tương ứng. Phân hệ \textbf{Automatic Documentation Update on Source-Code Change} thuộc hệ thống \textbf{Living Docs} giải quyết triệt để vấn đề này bằng cách:
\begin{itemize}
    \item Lắng nghe tự động các sự kiện thay đổi mã nguồn từ GitHub Webhook (Push Commit, Open/Update PR, Merge PR).
    \item Sử dụng phân tích cây cú pháp trừu tượng (Abstract Syntax Tree - AST) kết hợp mô hình AI (LLM + RAG) để xác định chính xác các thực thể mã nguồn bị ảnh hưởng (Class, Method, Endpoint, Parameter, Dependency) và tự động sinh bản thảo tài liệu cập nhật tương ứng.
    \item Đưa các bản cập nhật tài liệu tự động vào quy trình kiểm duyệt nghiêm ngặt với 3 vai trò (AI, Staff Reviewer, Manager Approver) trước khi lưu hoặc merge chính thức vào kho lưu trữ (Repository).
    \item Cung cấp khả năng so sánh khác biệt (Diff View), ghi vết lịch sử thay đổi (Change Log) chỉn chu và hỗ trợ khôi phục (Rollback) phiên bản tài liệu an toàn.
\end{itemize}

\subsection{Phạm vi và Nhiệm vụ (Task 3)}
Nhiệm vụ Task 3 do \textbf{Anh Kiệt} đảm nhận tập trung vào các chức năng cốt lõi sau:
\begin{enumerate}
    \item \textbf{Tự động kích hoạt cập nhật tài liệu} ngay khi phát hiện thay đổi mã nguồn trong Commit/PR.
    \item \textbf{Cấu hình linh hoạt} bật/tắt tính năng auto-update cho từng Repository, Module hoặc Document cụ thể.
    \item \textbf{Giao diện hiển thị và So sánh Diff} giữa phiên bản AI tự động cập nhật và phiên bản hiện tại đang phát hành.
    \item \textbf{Quy trình xử lý phản hồi từ Developer}: Cho phép Chấp nhận (Accept), Chỉnh sửa (Edit), Bỏ qua (Dismiss), hoặc Yêu cầu sinh lại (Regenerate).
    \item \textbf{Khôi phục phiên bản (Rollback)} tài liệu về trạng thái trước khi diễn ra đợt tự động cập nhật.
\end{enumerate}

\subsection{Mô tả Chi tiết từng Use Case}

\subsubsection{UC-AU-01: Tự động cập nhật tài liệu khi mã nguồn thay đổi}
\begin{itemize}
    \item \textbf{Actor}: System (GitHub Webhook / Event Bus), Developer.
    \item \textbf{Pre-conditions}: Repository đã được kết nối với Living Docs và bật tính năng Auto-Update.
    \item \textbf{Trigger}: Developer push commit hoặc tạo/cập nhật Pull Request trên GitHub.
    \item \textbf{Main Flow}:
        \begin{enumerate}
            \item GitHub gửi sự kiện Webhook (\texttt{push} hoặc \texttt{pull\_request}) đến hệ thống Living Docs.
            \item Service \texttt{CodeAnalysisService} thực hiện phân tích AST Code Diff để trích xuất các hàm, lớp, API endpoint bị sửa đổi.
            \item Service \texttt{RagRetrievalService} truy vấn Knowledge Base để tìm các tài liệu liên quan đến các thực thể mã vừa thay đổi.
            \item AI Engine (Python FastAPI) nhận thông tin Code Diff, Template, và Tài liệu hiện tại để sinh ra bản dự thảo tài liệu mới (Draft Auto-Updated Version).
            \item Hệ thống lưu trữ bản nháp mới, đánh dấu trạng thái \texttt{PENDING\_DEV\_ACCEPTANCE} hoặc tự động đẩy vào luồng \texttt{IN\_REVIEW} theo chính sách cấu hình.
            \item Gửi thông báo đến Developer liên quan qua UI/Email/Slack.
        \end{enumerate}
    \item \textbf{Post-conditions}: Phiên bản tài liệu mới được tạo và liên kết chính xác với Commit Hash và Code Diff.
\end{itemize}

\subsubsection{UC-AU-02: So sánh Diff và Duyệt bản Cập nhật Tự động}
\begin{itemize}
    \item \textbf{Actor}: Developer / Author.
    \item \textbf{Pre-conditions}: Tài liệu đã có bản AI Auto-Updated ở trạng thái chờ duyệt.
    \item \textbf{Main Flow}:
        \begin{enumerate}
            \item Developer truy cập màn hình chi tiết tài liệu hoặc danh sách thông báo Auto-Update.
            \item Chọn xem khác biệt (Diff View) để so sánh song song (Side-by-Side) bản đang phát hành và bản AI đề xuất.
            \item Hệ thống hiển thị bằng màu sắc (Xanh: Thêm mới, Đỏ: Xóa, Vàng: Chỉnh sửa).
            \item Developer thực hiện một trong các thao tác:
                \begin{itemize}
                    \item \textbf{Accept}: Đồng ý nội dung, chuyển tài liệu sang hàng chờ kiểm duyệt của Staff (Staff Review Queue).
                    \item \textbf{Edit}: Mở trình soạn thảo Markdown/WYSIWYG để chỉnh sửa lại nội dung do AI sinh ra trước khi gửi Review.
                    \item \textbf{Dismiss}: Bỏ qua bản cập nhật AI nếu thay đổi trong mã không ảnh hưởng tới tài liệu.
                \end{itemize}
        \end{enumerate}
\end{itemize}

\subsection{Kiến trúc Phân hệ Cập nhật Tự động}
Phân hệ Auto Update hoạt động theo mô hình Event-Driven Microservices kết hợp với AI Engine:
\begin{itemize}
    \item \textbf{Spring Boot Backend (Core Service)}: Lắng nghe GitHub Webhook qua Kafka Topic \texttt{code-change-events}, quản lý quy trình nghiệp vụ và lưu trữ PostgreSQL.
    \item \textbf{Python FastAPI (AI Service)}: Phân tích AST, thực hiện RAG trên Vector Store và gọi LLM (OpenAI/Claude/Local LLM) để cập nhật tài liệu.
    \item \textbf{PostgreSQL Database}: Lưu trữ Version History, Change Logs, Document Metadata.
    \item \textbf{Redis Cache}: Lưu trữ tạm thời trạng thái Diff và session duyệt của người dùng.
\end{itemize}

  1. RAG Query: Tim cac Document Chunk chua keyword 'getPaymentStatus'.
  2. Prompting LLM: "Cap nhat doan van ban tai lieu sau theo Code Diff moi..."
  3. Tra ve JSON: { document_id, updated_content, confidence_score, diff_summary }

[Spring Boot Backend]
  1. Tao Record moi trong bang `document_versions`:

     - created_by_role = 'AI'
     - trigger_type = 'COMMIT'
     - trigger_ref = 'commit_sha_123456'

  2. Tao Audit Record trong bang `document_change_logs`.
  3. Ban WebSockets Notification toi Web Client cua Author.

\subsection{Sơ đồ Thực thể Mối quan hệ (ERD - Table Schemas)}

\begin{lstlisting}[language=SQL, caption={Cấu trúc Dữ liệu PostgreSQL cho Phân hệ Auto Update}]
-- Bang quan ly Thong tin Tai lieu
CREATE TABLE documents (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    repository_id UUID NOT NULL,
    title VARCHAR(255) NOT NULL,
    file_path VARCHAR(500) NOT NULL,
    current_version_id UUID,
    auto_update_enabled BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Bang quan ly Phiên ban Tai lieu (Document Versions)
CREATE TABLE document_versions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    version_number VARCHAR(20) NOT NULL, -- Vi du: "1.2.0-draft", "2.0.0"
    content TEXT NOT NULL,
    created_by_role VARCHAR(20) NOT NULL, -- 'AI', 'DEVELOPER', 'STAFF', 'MANAGER'
    created_by_user_id UUID,
    trigger_type VARCHAR(30) NOT NULL, -- 'COMMIT', 'PULL_REQUEST', 'MANUAL_REGEN', 'ROLLBACK'
    trigger_commit_hash VARCHAR(40),
    pull_request_number INT,
    confidence_score FLOAT, -- Điểm tin cậy của AI (0.0 - 1.0)
    status VARCHAR(30) NOT NULL, -- 'DRAFT', 'PENDING_DEV', 'IN_REVIEW', 'APPROVED', 'REJECTED', 'PUBLISHED'
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Bang Nhat ky Thay doi (Change Log & Audit Trail)
CREATE TABLE document_change_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    from_version_id UUID REFERENCES document_versions(id),
    to_version_id UUID REFERENCES document_versions(id),
    acting_role VARCHAR(20) NOT NULL, -- 'AI', 'STAFF', 'MANAGER'
    action_type VARCHAR(50) NOT NULL, -- 'AUTO_UPDATE_GENERATED', 'DEV_ACCEPTED', 'STAFF_APPROVED', 'ROLLBACK'
    change_summary TEXT,
    grounding_evidence JSONB, -- Luu tru { code_diff, commit_sha, file_path, lines }
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Bang Cau hinh Auto-Update per Repo/Module
CREATE TABLE auto_update_configs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    repository_id UUID NOT NULL,
    module_path VARCHAR(255),
    is_auto_update_active BOOLEAN DEFAULT TRUE,
    require_staff_review BOOLEAN DEFAULT TRUE,
    require_manager_approval BOOLEAN DEFAULT TRUE,
    updated_by UUID,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

\subsection{Màn hình So sánh Khác biệt (Side-by-Side Diff View)}
Giao diện hiển thị trực quan khác biệt giúp Developer nhanh chóng nhận biết những chỉnh sửa do AI đề xuất:
\begin{itemize}
    \item \textbf{Cột Trái (Published Version)}: Hiển thị nội dung tài liệu hiện tại đang áp dụng trên hệ thống.
    \item \textbf{Cột Phải (AI Auto-Updated Version)}: Hiển thị nội dung do AI tự động cập nhật dựa trên Code Commit mới nhất.
    \item \textbf{Khối Bằng chứng (Grounding Evidence Box)}: Đính kèm đường link dẫn tới Commit SHA, Pull Request, và dòng mã nguồn bị thay đổi trong file repository.
    \item \textbf{Thanh Công cụ Hành động (Action Bar)}:
        \begin{itemize}
            \item Nút \textbf{[Accept \& Submit for Review]}: Duyệt bản cập nhật và chuyển sang bước Staff Review.
            \item Nút \textbf{[Edit Draft]}: Chuyển sang chế độ chỉnh sửa trực tiếp trên Editor.
            \item Nút \textbf{[Regenerate]}: Gửi yêu cầu AI phân tích lại mã nguồn và tạo bản thảo mới.
            \item Nút \textbf{[Dismiss]}: Tối ưu bỏ qua bản gợi ý nếu không cần thiết.
        \end{itemize}
\end{itemize}

\subsection{Màn hình Lịch sử Phiên bản \& Khôi phục (Version History \& Rollback)}
\begin{itemize}
    \item Hỗ trợ dạng dòng thời gian (Timeline View) liệt kê danh sách toàn bộ các phiên bản đã được ghi nhận.
    \item Mỗi cột mốc hiển thị rõ: \textbf{Tên phiên bản}, \textbf{Tác nhân thực hiện} (biểu tượng AI, Staff hoặc Manager), \textbf{Thời gian}, và \textbf{Lý do/Commit liên quan}.
    \item Nút \textbf{[Rollback to This Version]}: Cho phép người dùng có thẩm quyền (Developer / Technical Lead) bấm khôi phục tài liệu về đúng trạng thái tại phiên bản được chọn. Một bản ghi Change Log loại \texttt{ROLLBACK} sẽ tự động được khởi tạo để đảm bảo tính minh bạch.
\end{itemize}

\section{Cài đặt Thực nghiệm \& Mã nguồn Minh họa (Implementation Snippets)}

Dưới đây là đoạn mã ví dụ triển khai Service xử lý sự kiện Auto-Update trong Java Spring Boot và AI Engine trong Python.

\subsection{Java Spring Boot: Listener xử lý sự kiện Auto Update}

\begin{lstlisting}[language=Java, caption={AutoUpdateEventListener.java trong Spring Boot}]
package com.livingdocs.service;

import com.livingdocs.dto.CodeChangeEvent;
import com.livingdocs.model.DocumentVersion;
import com.livingdocs.repository.DocumentVersionRepository;
import org.springframework.kafka.annotation.KafkaListener;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class AutoUpdateEventListener {

    private final AiEngineClient aiEngineClient;
    private final DocumentVersionRepository versionRepository;
    private final NotificationService notificationService;

    public AutoUpdateEventListener(AiEngineClient aiEngineClient, 
                                  DocumentVersionRepository versionRepository,
                                  NotificationService notificationService) {
        this.aiEngineClient = aiEngineClient;
        this.versionRepository = versionRepository;
        this.notificationService = notificationService;
    }

    @KafkaListener(topics = "code-change-events", groupId = "living-docs-auto-update")
    @Transactional
    public void handleCodeChange(CodeChangeEvent event) {
        // 1. Kiem tra cau hinh auto-update cua Repo
        if (!isAutoUpdateEnabled(event.getRepositoryId())) {
            return;
        }

        // 2. Goi AI Engine de sinh noi dung cap nhat
        AutoUpdateResult result = aiEngineClient.generateUpdatedDoc(event);

        if (result.hasChanges()) {
            // 3. Luu phien ban Auto-Updated moi
            DocumentVersion newVersion = new DocumentVersion();
            newVersion.setDocumentId(result.getDocumentId());
            newVersion.setContent(result.getUpdatedContent());
            newVersion.setCreatedByRole("AI");
            newVersion.setTriggerType("COMMIT");
            newVersion.setTriggerCommitHash(event.getCommitHash());
            newVersion.setConfidenceScore(result.getConfidenceScore());
            newVersion.setStatus("PENDING_DEV");

            versionRepository.save(newVersion);

            // 4. Gui thong bao cho Author/Developer
            notificationService.notifyDeveloper(event.getAuthorId(), newVersion.getId());
        }
    }
